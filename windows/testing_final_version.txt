================================================================================
 BUGS FOUND
================================================================================

1. program_board.ps1 -m RELATIVE PATH BUG
   - SEVERITY: Medium
   - DESCRIPTION: When -m is given a relative path (e.g., "output\BRS-100-GW1NR9.fs"),
     the script passes it directly to programmer_cli.exe without resolving to an
     absolute path. programmer_cli.exe cannot find the file and fails with exit
     code 80: "Not found any data File".
   - EXPECTED: The script should resolve relative paths to absolute paths using
     (Resolve-Path $CustomBitfile).Path or similar before passing to programmer_cli.
   - WORKAROUND: Use full absolute paths with -m flag.
   - REPRO: .\program_board.ps1 -m output\BRS-100-GW1NR9.fs

================================================================================
 KNOWN ISSUES ENCOUNTERED DURING TESTING
================================================================================

1. FTDI USB STATE CORRUPTION
   - After programmer_cli.exe hangs and is killed, the FTDI USB device enters
     a bad state (USB location shows as 0, FT_Open returns status=3).
   - Recovery requires physical USB cable unplug/replug (3+ seconds).
   - The FT_CyclePort mechanism in the script helps prevent hangs on subsequent
     runs when the USB state is still clean, but cannot recover from a
     fully corrupted state.
   - This is documented in windows\TROUBLESHOOTING.txt.

2. EXECUTION POLICY
   - Scripts require PowerShell execution policy to be set to RemoteSigned
     or run with -ExecutionPolicy Bypass flag.
   - Without this, scripts fail with "UnauthorizedAccess" error.
   - This is documented in windows\README.md.
